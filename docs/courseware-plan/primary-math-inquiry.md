# 小学数学探究合同
# Primary Math Inquiry Contract

> 适用学段：小学 `g3-g6`，分类 `math`。
> 本文件定义「什么样的数学课件算让孩子自己发现了规律」，是小学数学课件改造与新增的判据。
> 初高中实验课件另有独立合同，见 [`secondary-labs.md`](./secondary-labs.md)；两者**并列但不同源**，不得互相套用。

## 审计结论

- **结论：ACCEPT**
- **核心价值：** 小学数学 32 个规划项已全部上线，课标知识点覆盖表几乎铺满，缺口不在「知识点」而在「知识的获得方式」。2026-08-24 对 26 个 `g3-g6` 数学课件逐个读码实测：**M1 二十个、M2 六个、M3 及以上为零**。绝大多数课件的形态是「操作 → 即时反馈 → 系统文案给出规律」，孩子是操作者和见证者，不是归纳者。
- **现有门禁为何发现不了：** `status.md` 的完成定义检查玩法闭环、双语、主题、触屏、音效、构建通过；`facts.md` 检查知识**正确性**。没有任何一条检查知识是**怎么到孩子脑子里的**。这是验收面本身缺一个维度，不是执行走样。
- **主要风险：** 最大风险不是改动量，而是**把初高中的物理测量合同直接套到数学上**，教出「数学结论是测量出来的经验规律」这种错误数学观。其次是把探究做成填表作业，让孩子多了负担却没多出发现。

## 为什么不复用初高中实验合同

`secondary-labs.md` 的 L3 要求「仪器、量程、有效数字、单位、误差、数据表、图像」。这套合同适用于物理化学，因为那里的结论是**经验规律**，会被更精密的测量修正。

数学不是这样。三角形内角和 180° 不是测量 100 个三角形取平均得到 179.8°，它是必然的；再精密的量角器也不会修正它。如果用测量合同去教，孩子会形成一个错误的认识：数学结论和物理结论一样，是从观测里统计出来的。**这个错误比现在的判题式更难纠正，因为它披着「严谨」的外衣。**

数学探究的本质是另一条链：

```text
提出问题 → 形成预测 → 构造多个实例 → 记录进实例表
    → 从表中读出不变量 → 写下猜想 → 主动寻找反例或临界
    → 确定结论的适用范围 → 迁移到新情境
```

与测量链的关键差异有三处。数学的实例是**精确构造**的，不存在测量误差，因此不需要重复测量取平均；数学的验证靠**穷举边界与寻找反例**，而不是提高仪器精度；数学的结论一旦成立就是**必然的**，课件的措辞必须守住这一点。

## 北极星：三类探究模型

小学数学不是一种探究，是三种。用统一合同一定会在某一类上失真。

### A 测量型

**范围：** 量与计量领域，以及少数需要真实读数的几何内容。角的度量、长度、体积、圆周率。

**这一类可以直接复用 `secondary-labs.md` 的 L3 测量合同**，不必发明新东西：有仪器、有单位、有读数、有容差。

**边界提醒：** π 是数学常数，滚轮测量只是「发现它存在且恒定」的手段，不是它的定义。这一点必须写进对应课件的 `facts.md`，避免暗示 π 的值由测量决定。

**闭环：** 提出问题 → 预测读数 → 只改一个量 → 测量并读数 → 记入数据表 → 从表中看出比例或函数关系 → 结论 + 适用范围。

### B 归纳-反例型

**范围：** 数与代数、图形与几何的主体。这是小学数学课件的大多数。

**闭环：** 提出问题 → 预测 → 构造 ≥3 个实例 → 记入实例表 → 读出不变量 → 写下猜想 → 主动找反例或逼近临界 → 确定适用条件。

**举例说明改造前后的差别。** 三角形三边关系现在的做法是：给三根签子，问「能围成 / 围不成」，二选一。探究版是：固定 3 和 4，用滑块连续拉长第三根，孩子自己盯着找到「恰好围不成」的那一瞬间是 7；然后换成 2 和 5，临界值是几？填满三行实例表，规律自己浮出来。**7 这个临界值必须是孩子逼出来的，不能是课件说出来的。**

### C 统计-随机型

**范围：** 统计与概率。

**闭环：** 提出问题 → 预测 → 固定种子多轮试验 → 频率表逐轮累积 → 观察频率趋近理论值 → 结论 + 说明「趋近」不等于「相等」。

**硬要求：** 随机必须用显式种子，同种子同参数必须复现同结果，否则 E2E 无法断言，也无法排除用随机数掩盖模型错误。多轮试验的频率必须**逐轮累积并排**，不能重跑覆盖——覆盖式重跑看不出收敛。

### D 约定型：明确排除

**范围：** 知识点本身是人为约定、记法或公理，**不可能被「发现」**。包括：十进制满十进一、分数与小数记法、万/亿分级命名、负号与数轴方向、坐标数对的书写次序、等式性质（公理）、时刻读法、货币面值。

**对这类课件不适用探究合同，深度上限为 M2。** 它们的目标是「约定呈现得足够清晰 + 熟练应用」，不是发现。硬推 M3 就是假探究——让孩子「归纳」出一个本来就是人定的规则，是在教一种错误的认识论。

在 `status.md` 中必须标注为 D 类，避免后续有人拿探究指标去考核它们。

## 探究深度分级

| 等级 | 判定标准 | 用途 |
| --- | --- | --- |
| M1 观察 | 改参数看现象，或出题→作答→对错反馈。结论由课件文案给出 | 概念引入，不单独算完整探究课件 |
| M2 对照 | 能固定其余量、只改一个，两种配置的结果可前后或并排比较 | 约定型课件（D 类）的上限 |
| M3 归纳 | 见下方两条硬判据，必须同时满足 | **新增与改造的最低要求** |
| M4 反例/边界 | 在 M3 基础上，主动找到反例、临界值，或说清适用条件 | 首批改造课件至少提供一个 M4 挑战 |

### M3 的两条硬判据

**判据一 · 累积展示。** 存在一个在多次试验之间**不被清空**的记录容器，同屏渲染 ≥3 行实例。

不算数的情况：关卡进度计数器（`triangle-lab` 的 `recordCount` 显示 `0/3`，那是三个实验各自完成与否，不是数据）；撤销栈；只显示当前一次的读数区；开局就列出全部待填空位的收集墙。

**三行必须是三次独立试验，不是一次试验的三个中间状态。** `icecream-geometry` 原本会依次显示「已倒 1 杯 / 2 杯 / 3 杯」，看着像三行记录，实际是同一次实验的过程——孩子只能读出「这次是 3 杯」，读不出「不管杯子多大都是 3 杯」。判据一要的是能支撑归纳的独立实例。

**判据二 · 结论归属。** 规律、公式或不变量的文本，**不得**在孩子提交猜想之前出现在 `lesson` / `tip` / `hint` / `status` / `toast` / `formula` 的任何位置。

这一条是当前最普遍的失分点。实测中反复出现同一个模式：孩子把数据都做出来了，系统抢先把结论说了。`rolling-park` 已经有完整的直径-周长-比值记录表，却在第 3 条记录出现时弹出「这个固定的倍数就是 π」；`icecream-geometry` 倒满第 3 杯时亮起 `×1/3` 灯牌；`crystal-cave` 把唯一分解定理写进了证书颁奖词。

**它管的是「关系」，不是「术语」。** 标题写「把 π 亲手滚出来」、徽章上印一个 π 字符，都不算违反：孩子只知道要去找一个叫 π 的东西，不知道它等于几、更不知道它是谁比谁。违反的是把关系说出来——「周长是直径的 3.14 倍」「这个固定的倍数就是 π」。悬念式命名反而是好设计，`rolling-park` 改造时予以保留。

**它的作用域看 tab 顺序，不是笼统的「探究流内」。** 排在探究站**之后**的推导演示与应用练习（`rolling-park` 的 B「拼面积」、C「算路程」，`icecream-geometry` 的「营业挑战」）可以正常出现 `πr²`、`÷3`，那是教学顺序使然，不必加 tab 门禁——门禁会毁掉自由探索。

但**默认站、以及排在探究站之前的站，同样受判据二约束**。`icecream-geometry` 就栽在这里：它的默认站「旋转成型机」一转出圆锥就显示 `V = πr²h÷3`，而探究站「三倍之谜」排在它后面——孩子还没开始倒冰淇淋，答案已经给完了。这类地方把结论改成悬念即可：现在显示 `V = πr²h ÷ ？　去「三倍之谜」量出这个数`，孩子在探究站报出 3 之后回来才看到补全。两站因此被串成一条线，比原先更好。

**但它延伸到 `course.json` 的 `description`。** 这是首个样板才暴露的第三个泄底面：`rolling-park` 的简介原文是「画出的线总是直径的 3.14 倍——这个倍数就是 π」，主站卡片在孩子点进课件**之前**就把猜想答案摆出来了。简介同时服务于成人选课与检索，不能删空，处理原则是**留术语、去数值与关系**：`π`、`πr²` 这类主题词保留，「总是直径的 3.14 倍」这类答案删掉。

逐条读完 26 个 g3-g6 数学课件的简介后，剧透的有 5 个，全部落在第一、二梯队：

| 课件 | 简介里的剧透 | 本该由孩子发现的 |
| --- | --- | --- |
| `rolling-park` | 「总是直径的 3.14 倍——这个倍数就是 π」 | 周长与直径的比值恒定（已改） |
| `icecream-geometry` | 「一杯、两杯、三杯刚好满，×1/3 的秘密」 | 等底等高时锥是柱的三分之一 |
| `hamster-fence` | 「同样的周长，围法不同面积天差地别」 | 周长固定时面积会变 |
| `triangle-lab` | 「把三角形三个角拼成平角」 | 内角和是 180° |
| `lantern-lane` | 「两端、一端、环形其实是同一道间隔题」 | 三种情形可统一 |

`carnival-truth` 的「用稳定下来的频率」属轻度，频率收敛正是它要孩子看见的。占非约定型课件的四分之一强，**不是个例；改造某个课件时必须把 `course.json`、canvas 绘制文案、面板文案三处一起过一遍。**

顺带一个方法论教训：这份清单第一次是用正则扫「就是 / 总是 / 等于 / 倍数」得出的，结论是「只有 `rolling-park` 一个」——完全错。`×1/3`、「三杯刚好满」、「天差地别」都能绕开任何关键词表。**判据二没法靠文本扫描自动化**，详见「机器验收面」。

## 改造批次

批次划分不按主观偏好，按两个客观条件的交集：是否为约定型（能否被探究）、是否有专属 E2E 断言（改动是否撞既有测试）。

### 第一梯队 · 5 个 · 零测试阻力

非约定型且只有 smoke 覆盖，改造不撞既有断言。这 5 个恰好覆盖 π、圆锥体积、周长面积极值三个最强不变量。

| 课件 | 知识点 | 改造动作 | 目标 |
| --- | --- | --- | --- |
| `rolling-park` | 圆周率 π | 移除第 3 条记录时的 π 播报，改为让孩子从表里读出比值再确认 | M3，方轮扩展为 M4 反例 |
| `icecream-geometry` | 圆锥 = 圆柱的 1/3 | 撤掉 `×1/3` 灯牌与 magic toast，第 3 杯倒满后让孩子填倍数 | M3，不等底等高为 M4 边界 |
| `hamster-fence` | 同周长不同面积 | 新增 (长,宽,周长,面积) 累积表，1×7 与 4×4 并排留存 | M3，正方形极值为 M4 |
| `volume-aquarium` | 排水法测体积 | 新增「物件｜猜想｜排水读数」三列记录，toast 不再直接报答案 | M3（A 类，套 L3 测量合同） |
| `voxel-studio` | 三视图定体 | 预测记录跨关保留，系统自动演示的反例改为孩子自己构造 | M3，双雕塑同视图为 M4 |

#### 已完成：`rolling-park`（首个样板）

实际改动比计划多一处。除了第 3 条记录时的 π 播报，`drawRoll()` 还在**第一次**滚完就往画布贴了「≈ 3.14 个直径，这个倍数就是 π」，泄底比审计时发现的那处更早，现改为「数数看：这条线有几个直径？」。攒够 3 组不同直径后出现猜想卡，孩子填出 2.9–3.3 之间的数才揭示「它叫 π」并点亮 `#piBadge.awake`；填错只提示回表格看，不报答案。深链 `?state=guess` 直达猜想态供课堂演示。配套补了 `facts.md`（移出 `scripts/facts-legacy.json`）与 `tests/e2e/rolling-park.spec.js`。

**计划里的 M4（方轮反例）没有做。** 方轮的「周长 ÷ 对角线」在小学阶段没有教学意义，硬塞会把一次干净的 π 归纳变成两套并行的比值概念。方轮维持原样、只演示滚动平不平稳，E2E 反过来锁定它不混进实测记录。这个课件停在 M3；M4 交给 `hamster-fence` 的正方形极值更合适——那里的边界是同一个量取极值，不需要引入新概念。

#### 已完成：`icecream-geometry`

**这个课件证明了：达到 M3 有时要改数据模型，不只是改文案。** 原本只有一组固定尺寸的杯子，「倒 3 杯刚好满」是一次测量，凑不出判据一要的三个归纳实例。现在改成大、中、小三组等底等高的杯子，每组各倒满一次，三行结果并排留在表里，孩子从「三次都是 3 杯」读出与大小无关。第二梯队的工作量要按这个标准重估，不能只按文案改动量。

泄底点也比 `rolling-park` 多，而且藏在 3D 场景里：悬在半空的 `× 1/3` 霓虹灯（原本半透明常驻，一进站就能看见）、圆柱杯壁上的 `1/3 · 2/3 · 3/3` 三等分刻度标签（等于直接告诉孩子答案是 3）、读数区的「圆锥 = 圆柱的 ⅓」、倒满时的 `magic` 播报、默认站的 `÷3` 公式、以及 `course.json` 简介。刻度标签直接删掉——满不满看液面到没到杯口就够了，「三等分」这件事必须由孩子自己数出来。

M4 用现成的「换个小杯子对照」实现：不等底等高时倒 4 杯仍不满。文案拆成两条，猜对前只给中性观察（「倒了 4 杯还是没满」），猜对后才解释（「÷3 只在等底等高时成立」）。

一个 3D 课件特有的坑：杯口的「满」字标签是 `THREE.Sprite` 贴图，切换语言时不会自动更新，必须在 `applyLang()` 里重建整个 triple 场景。用 canvas/WebGL 画文字的课件都要注意这条。

### 第二梯队 · 14 个 · 需同步改 E2E

合计 465 条 `expect` 断言锁定当前判题流程，逐个推进，不批量改。撞测试是预期行为，说明改动确实触及了核心交互。

其中 `triangle-lab` 改动最彻底：删掉动手前给结论的 `lessonText`，三边关系从二选一按钮改为拉动第三边逼近临界值。

### 第三类 · 7 个 D 类 · 不推 M3

在 `status.md` 标注为约定型、上限 M2。目标改为「约定呈现清晰 + 熟练应用」。`balance-circus` 是特例：`historyList` 已具 M3 骨架，但等式性质是公理，做到 M2 的极致即可。

## 数据协议

先定协议，不造通用框架——沿用 `secondary-labs.md` 的既有决策。每个达到 M3 的课件至少能表示：

```json
{
  "version": 1,
  "inquiryLevel": "M3",
  "inquiryKind": "B",
  "seed": 42,
  "question": "三根木条什么时候围不成三角形？",
  "instances": [
    { "construct": { "a": 3, "b": 4, "c": 6 }, "observe": { "closes": true } }
  ],
  "conjecture": "a + b > c",
  "counterexamples": [{ "a": 3, "b": 4, "c": 7 }]
}
```

`inquiryKind` 取 `A` / `B` / `C` / `D`。D 类课件的 `inquiryLevel` 不得超过 `M2`。

**这份协议不落在 `course.json` 里。** 首个样板实现时发现：`scripts/build.mjs` 生成清单时对课件元数据整体展开（`{ ...meta, keywords, path }`），任何新增字段都会进入 `courseware/index.json`，而该文件又在 Service Worker 预缓存名单内——探究元数据会变成每个访客都要下载的主站资源。真要落地时走独立的 `src/<id>/inquiry.json`，与 `facts.md` 同属「审核靶子」：只参与构建校验，不进产物。在有三个课件证明这些字段确实够用之前，不引入该文件。

等到三门课件证明某个记录表或猜想板的实现确实重复，再抽取共享组件；抽取时只能走 `scripts/sdk/core.js` 内联注入这条路径，不得让课件互相引用——`AGENT.md` 的运行时独立铁律不变。

## 技术与边界

1. **课件运行时保持完全独立。** 探究记录表由各课件自行实现，不跨目录引用。
2. **随机必须可复现。** C 类课件的种子由课件自身固定（URL 参数或模块常量），E2E 能加载固定种子重放同一轮试验。不要写进 `course.json`，理由见「数据协议」。
3. **不伪装必然性。** A 类课件涉及测量时，必须在 `facts.md` 写明「测量是发现常数的手段，不是常数的定义」。
4. **实例表不是作业本。** 记录应当由操作自动落表，不要求孩子手工誊写；填空只用在最后的猜想环节。这是本合同最容易走偏的地方。
5. **手机不压缩桌面面板。** 375×667 用「构造 → 记录 → 猜想」分步页，桌面可同屏显示实验台与实例表，两者共享同一状态。
6. **`facts.md` 增列猜想。** 课件让孩子归纳出的每条猜想，都要作为断言写进 `facts.md` 并标注来源。

## 机器验收面

数学在这件事上有物理没有的优势：**猜想都有精确 oracle，多数不需要容差。**

| 设计元素 | 验证手段 |
| --- | --- |
| 猜想正确性 | 纯函数断言，如对随机生成的 1000 个三角形断言内角和为 180 |
| 反例集有效性 | golden cases：`(3,4,7)` 必须判定为退化，`(3,4,6.99)` 必须成立 |
| 临界值精度 | 参数化断言：固定 a、b，二分逼近的临界 c 等于 `a+b` |
| 实例表可复现 | 固定种子生成实例序列，断言表内容逐格相同 |
| A 类测量收敛 | 断言比值在全部参数下落在同一容差带内（仅 A 类需要容差） |
| C 类随机复现 | 同 `seed` 同参数，逐轮频率表完全一致 |
| 探究闭环 | E2E：预测 → 构造 3 个实例 → 提交猜想 → 触发反例 → 修正结论，桌面与 375×667 各一次 |
| 结论归属（判据二） | E2E 断言「揭示态」标记 + 揭示前的 DOM 文案。**不要指望构建期文本扫描** |

**判据二不能靠文本扫描验收。** 合同初稿设想「构建校验扫描猜想的关键表述有没有出现在揭示前的 i18n key 里」，实测证明这条路走不通：泄底的自然语言千变万化，`×1/3`、「三杯刚好满」、「天差地别」能绕开任何关键词表，而「把 π 亲手滚出来」这类合规的悬念命名又会被误伤。**正确的验收方式是行为断言，不是文本匹配。**

**另一层盲区：画在 canvas 上的文字是位图，E2E 断言不到。** `rolling-park` 原先在第一次滚完就往画布贴「≈ 3.14 个直径，这个倍数就是 π」——比面板上的播报泄底更早，而任何 DOM 断言都发现不了它。canvas 型课件的判据二必须由代码审查兜底：改造时逐个核对绘制函数引用的文案 key。

**推荐给每个课件落一个「揭示态」标记。** 让知识点的视觉奖励（徽章高亮、公式点亮）统一由一个 class 控制，且只在孩子提交猜想后添加，E2E 就能拿它当判据二的代理信号：揭示前断言其不存在，揭示后断言其存在。`rolling-park` 用 `#piBadge.awake` 实现，比逐条核对文案稳定，也不受 canvas 盲区影响。

**人工验收点：** 学科教师核对猜想措辞是否会让孩子以为数学结论是测出来的；目标年级学生检查填实例表是否变成负担。**探究退化成填表作业是最大的人工验收风险，smoke 测不出来。**

## 完成定义

一个小学数学课件按本合同完成，需同时满足：

- `inquiryLevel` 达到 M3 或以上（D 类课件为 M2），不是只有参数滑块和现象动画。
- 满足 M3 两条硬判据：记录容器跨试验不清空且同屏 ≥3 行；结论文本在孩子提交猜想前不出现。
- 猜想、反例、临界值通过自动化断言；`facts.md` 增列对应断言并注明来源。
- `AGENT.md` 的既有质量规约全部照旧：双语、深浅主题、静音、桌面与手机布局、儿童字号。
- `npm run build`、目标单元测试与目标 E2E 通过，`src/` 与 `courseware/` 同步。
- `status.md` 的探究深度列同步更新；等级变化时回写本文件的实测基线表。

## 与其他文档的关系

- [`math.md`](./math.md) 保持不变，它描述的是玩法与魔法时刻；本文件描述的是探究深度，两者正交。
- [`status.md`](./status.md) 是状态单一入口，探究深度作为新增列维护在那里，本文件只保留实测基线快照。
- [`secondary-labs.md`](./secondary-labs.md) 是初高中测量合同，与本文件并列。跨学段课件（如 `volume-aquarium` 的 A 类部分）以本文件为准，但可复用其 L3 测量条款。
